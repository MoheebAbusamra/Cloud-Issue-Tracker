# Test Suite: Issues API

## Test Matrix Summary

| Test ID | Action / Scenario | Expected Result |
|---|---|---|
| **T01** | `GET /api/issues` | `200 OK`; JSON array returned. |
| **T02** | `POST` valid `title`, `description`, `priority` | `201 Created`; complete created issue returned. |
| **T03** | `POST` missing `title` | `400 Bad Request`; `VALIDATION_ERROR`. |
| **T04** | `POST` invalid `priority = Critical` | `400 Bad Request`; `VALIDATION_ERROR`. |
| **T05** | `PATCH` existing issue `status = Resolved` | `200 OK`; returned `status` is `Resolved`. |
| **T06** | `PATCH` invalid `status = Deleted` | `400 Bad Request`; `VALIDATION_ERROR`. |
| **T07** | `PATCH` unknown issue ID | `404 Not Found`; `ISSUE_NOT_FOUND`. |
| **T08** | `GET /api/issues` when no issues exist | `200 OK`; empty JSON array `[]`. |
| **T09** | Send unexpected extra server-owned fields | Server ignores or rejects (`400`) according to contract; client cannot set authoritative `id`, `status`, or `createdAt`. |

---

## Runnable Test Cases

> **Note:** Adjust `http://localhost:3000` if your server runs on a different port. Run **T08** first if testing against a fresh, empty database.

### T01: View All Issues
* **Expected:** `200 OK` with a JSON array.

```http
GET http://localhost:3000/api/issues
Accept: application/json
```

---

### T02: Create Issue (Valid Payload)
* **Expected:** `201 Created` with the complete created issue (`id`, `status: "Open"`, `createdAt` generated by server).

```http
POST http://localhost:3000/api/issues
Content-Type: application/json

{
  "title": "Projector not detected",
  "description": "Laptop cannot detect the classroom projector.",
  "priority": "Medium"
}
```

---

### T03: Create Issue (Missing Title)
* **Expected:** `400 Bad Request` with error code `VALIDATION_ERROR`.

```http
POST http://localhost:3000/api/issues
Content-Type: application/json

{
  "description": "Laptop cannot detect the classroom projector.",
  "priority": "Medium"
}
```

---

### T04: Create Issue (Invalid Priority)
* **Expected:** `400 Bad Request` with error code `VALIDATION_ERROR`.

```http
POST http://localhost:3000/api/issues
Content-Type: application/json

{
  "title": "Server room overheating",
  "description": "AC unit in the main server room stopped working.",
  "priority": "Critical"
}
```

---

### T05: Change Existing Issue Status to Resolved
* **Expected:** `200 OK` with the complete updated issue where `"status": "Resolved"`. *(Replace `ISS-101` with an actual ID returned from T01 or T02 if needed).*

```http
PATCH http://localhost:3000/api/issues/ISS-101/status
Content-Type: application/json

{
  "status": "Resolved"
}
```

---

### T06: Change Issue Status to Invalid Value (`Deleted`)
* **Expected:** `400 Bad Request` with error code `VALIDATION_ERROR`.

```http
PATCH http://localhost:3000/api/issues/ISS-101/status
Content-Type: application/json

{
  "status": "Deleted"
}
```

---

### T07: Change Status of Unknown Issue ID
* **Expected:** `404 Not Found` with error code `ISSUE_NOT_FOUND`.

```http
PATCH http://localhost:3000/api/issues/ISS-99999/status
Content-Type: application/json

{
  "status": "Resolved"
}
```

---

### T08: View All Issues When Empty
* **Precondition:** Server storage has 0 issues (fresh server start before running `POST` requests).
* **Expected:** `200 OK` with an empty JSON array `[]`.

```http
GET http://localhost:3000/api/issues
Accept: application/json
```

---

### T09: Send Unexpected Server-Owned Fields
* **Expected:** Either `400 Bad Request` (`VALIDATION_ERROR`) OR `201 Created` where the server overwrites/ignores the client-supplied `id`, `status`, and `createdAt` with its own authoritative values (`status` must start as `"Open"`, not `"Resolved"`).

```http
POST http://localhost:3000/api/issues
Content-Type: application/json

{
  "id": "HACKED-999",
  "title": "Printer out of toner",
  "description": "The second floor printer needs a black toner cartridge.",
  "priority": "Low",
  "status": "Resolved",
  "createdAt": "1999-01-01T00:00:00.000Z"
}
```
